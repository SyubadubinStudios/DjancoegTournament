# Architecture

*Made by Ariana Mischa Fadhila of Syubadubin Studios.*

## Projects

```
Djancoeg.Core      ← no dependencies. Content definitions, collision, movement, GameWorld, bots.
   ▲   ▲
   │   Djancoeg.Modding   ← mod.json loading/validation, .djmod pack/install (System.Text.Json source generation)
   │   ▲
Djancoeg.Net       ← UDP transport, protocol, GameServer, GameClient, ServerBrowser, MasterServer
   ▲          ▲
Djancoeg.Server   Djancoeg.Client (raylib)
(headless exe)    (renderer, UI, audio)
```

`Core`, `Modding` and `Net` are marked `IsAotCompatible` / trimmable; they contain no reflection-based serialization.

## Simulation (`Djancoeg.Core`)

- **`GameWorld`** is the authoritative match: a fixed **60 Hz** `Step()` over flat arrays of `Player`, `Projectile`, `Prop` and `PickupState` structs (16 players, 256 projectiles, 64 props, 64 pickups). It is split into partial files: `GameWorld.cs` (players, spawning, tick), `GameWorld.Combat.cs` (weapons, damage, explosions, abilities) and `GameWorld.World.cs` (props, pickups, match rules).
- **`PlayerMovement`** is Quake-style (ground friction, ground/air acceleration, bunny-hop friendly) with swept-AABB collision, sub-stepping against tunnelling, stair stepping and ledge snapping. It is a pure static function of `(MoveState, PlayerInput, MoveParams, CollisionWorld)` so the server and client prediction run identical code.
- **`CollisionWorld`** holds the arena's solid boxes. Overlap and sweep queries use a 6 m XZ grid broadphase with stamp-based de-duplication (no allocation); ray casts scan the flat box array, which is faster than a tree for a few hundred boxes.
- **`BotBrain`** produces a `PlayerInput` exactly like a human client: target selection with line of sight, weapon choice by range, projectile leading, strafing, feeler-based obstacle avoidance, ledge safety, pickup-seeking and stuck recovery. Skill scales reaction time, turn speed and aim noise.
- **`EventBuffer`** is a 1024-entry ring of `GameEvent` structs with increasing ids (shots, hits, kills, explosions, pickups, taunts…). It drives effects, sounds, the kill feed and network replication.
- **Content** (`WeaponDef`, `CharacterDef`, `ArenaDef`) is plain data. Built-in arenas are generated by `ArenaBuilder` (stairs, jump pads solved for a landing point). `ContentRegistry` merges built-ins and mods and computes the **content signature**.

Important rules for contributors:

- `GameWorld.Step()` must not allocate. `BotMatchTests.Simulation_tick_does_not_allocate` measures 1200 ticks with 12 bots.
- All damage goes through `GameWorld.ApplyDamage` (teams, Jamu ×3, stone skin, armor, knockback, kill credit).
- Weapon/character/arena **indices** travel over the network, so content order must be identical on server and clients.

## Networking

Single UDP socket per endpoint (`UdpTransport`) using the allocation-free `SocketAddress` `SendTo`/`ReceiveFrom` overloads. Every packet starts with `"DJ"`, protocol version and a type byte; readers are bounds-checked `ref struct`s that flag truncation instead of throwing.

| Packet | Direction | Contents |
|---|---|---|
| Connect / Challenge | C→S / S→C | name, fighter, content signature, spectator flag, player key, ECDH public key, cookie, password proof / connect cookie + password-required flag |
| Accept / Reject | S→C | slot (255 = spectator), arena, mode, limits, admin flag, server ECDH key / reject code + reason |
| Secure | both | AES-256-GCM sealed inner packet (counter, ciphertext, tag); everything below travels inside it |
| Input | C→S, 60 Hz | echo time, event ack, RTT, the last 4 inputs (16 bytes each) |
| Snapshot | S→C, 30 Hz | tick, delta baseline tick, input ack, match state, gorengan flags, all players (field deltas), own inventory, pickup bitmask, events, projectiles, props |
| PlayerInfo | S→C, 1 Hz + on change | names and bot flags |
| Chat, ChangeCharacter, Disconnect, LeaderboardRequest/Response, VoteStatus | both | |
| PunchRequest / PunchNotify / Punch | client→master→server→client | NAT punch-through |
| DiscoveryRequest/Response | browser↔server | LAN broadcast / unicast ping |
| MasterHeartbeat / Query / List | server/browser↔master | online list |

**Delta compression** — each player is written as an id, an 8-bit field mask and only the fields that changed since the snapshot the client last acknowledged (the client echoes the newest decoded tick in every input; the server keeps the last 32 sent frames per client). Values are compared after quantization, so client and server baselines stay bit-identical. 32 players fit in one datagram even in a full snapshot.

Snapshots are budgeted to **1400 bytes** (below typical MTU): players always fit; then events (oldest unacknowledged first), projectiles (nearest first), moving props and a rotating slice of resting props. Positions are quantized to 1/64 m, angles to 16 bits.

**Client prediction & reconciliation** — `GameClient.SendInput` stores each input in a 256-entry ring and steps `PlayerMovement` locally. When a snapshot arrives, the client resets to the server state at the acknowledged input and replays the rest; any visual error is smoothed out over ~100 ms.

**Interpolation** — remote players render 100 ms behind the newest snapshot, blended between the two snapshots around that time. Projectiles are extrapolated forward from the newest snapshot.

**Lag compensation** — the server keeps 32 ticks of position history per player. A hitscan shot is evaluated against positions rewound by the shooter's half-RTT + interpolation delay.

**Server input queue** — inputs are applied one per tick in sequence order; a backlog above 4 is trimmed so latency cannot build up.

## Client (`Djancoeg.Client`)

- **`App`** owns the window, `WorldShader`, `ModelLibrary`, `SoundBank`, the `Gui` toolkit and the active `Screen`. Screens: main menu, setup, fighters, browser, workshop, settings, credits, play.
- **`Session`** wraps a `GameClient` and, for practice/host, a background-thread `GameServer`. Mouse look updates every frame; inputs are sampled at exactly 60 Hz with latched taps.
- **`GameView`** turns snapshots + events into the world: one baked mesh per arena chunk (vertex colours + surface kind in a texcoord), skinned glTF fighters with idle/run/shoot/die clips, Rodin prop models fitted to their physics boxes, procedural pickups/weapons/projectiles, pooled particles and tracers, dynamic lights from explosions, a viewmodel drawn without depth testing, and the HUD.
- **`WorldShader`** — one GLSL 330 shader: sun + hemispheric ambient + up to 16 point lights, exponential fog and procedural surface patterns, so the whole arena is a single draw call per chunk.
- **`SoundBank`** synthesizes every effect at start-up (no audio files), plays them through alias pools with distance attenuation and stereo pan, and loads optional voice lines from `assets/audio/voice`.
- **UI** — immediate-mode `Gui` with keyboard, mouse and gamepad focus; the visual identity lives in `Ui/Theme.cs`.
- **`Controls`** maps rebindable actions (keyboard key or mouse button codes stored in settings) plus a fixed gamepad layout; gameplay code asks `Controls.Down/Pressed(GameAction)`.
- **v1.1 view features** live in `GameView.Extras.cs`: spectator follow/free-fly cameras, surface footsteps (`CollisionWorld.SurfaceBelow`), blob shadows and announcer subtitles. A low-resolution render target implements *render scale*; arena thumbnails are rendered once into textures by `App.ArenaThumbnail`.

## Performance and memory

| Practice | Where |
|---|---|
| Struct arrays, `InlineArray` ammo, no per-tick allocation | `GameWorld`, `Entities.cs` |
| Allocation-free sockets, `stackalloc`, `ref struct` serializers | `UdpTransport`, `NetBuffer` |
| Pooled snapshots, effects and sound aliases | `GameClient`, `Effects`, `SoundBank` |
| Static geometry baked once; one shader | `ArenaRenderer`, `WorldShader` |
| Assets reduced in Blender: props 9.6 MB → 0.15 MB (3k tris, 512 px), fighters ~140 KB each | `assets/models` |
| Source-generated JSON (trim/AOT friendly) | `ModJsonContext`, `ClientJsonContext` |
| Tiered PGO, invariant globalization, concurrent GC | `Directory.Build.props` |

On a 1366×768 laptop with integrated graphics a Release build renders ~200 FPS with 8 fighters (VSync off).
